# Migrating the brain automation stack to another machine

This runbook brings the full brain automation stack up on a fresh **macOS** machine (e.g.
`junjun-server`). One command does the plumbing; a short checklist covers the parts that need
your account credentials.

> **Model:** every agent job runs headlessly as `claude -p "/goal …"` under **launchd**. There is
> no server process — launchd fires each job on a schedule. This is macOS-only; on Linux you would
> port the plists to systemd timers (not covered here).

---

## Architecture (what lives where)

| Piece | Location | In git? |
|---|---|---|
| Automation **code** — runner, registry, generators, watchdogs, gmail actions | `~/work/brain-ops` → `github.com/sonthanh/brain-ops` (**public**) | ✅ |
| **Vault** the jobs read/write | `~/work/brain` → `sonthanh/ai-brain` (**private**) | ✅ |
| Sibling repos the jobs edit | `~/work/brain-os-plugin`, `~/work/brain-geo-analysis-plugin` | ✅ |
| launchd **plists** | `~/Library/LaunchAgents/com.brain.*` | ❌ generated per-machine |
| Machine **config** | `~/.brain-os/brain-os.config.md` | ❌ generated by bootstrap |
| **Secrets** | `~/.config/brain/env` (Telegram alerts) | ❌ never in git |
| **Claude global layer** | `~/.claude/` (CLAUDE.md, hooks, enabledPlugins, auth) | ❌ personal — copied manually |

The plists are **generated on each machine** (`gen-automation-plists.ts`, `gen-ops-plists.ts`) so
the bun/node paths and `$HOME` resolve to the target machine — nothing is pinned to the source
Mac's username.

---

## Prerequisites

- macOS with **Homebrew** (`https://brew.sh`)
- Toolchain: `git`, `bun`, `node`, `gh`, `jq`, `claude` (Claude Code)
  - `brew install git bun node gh jq`
  - Claude Code: install from `https://docs.claude.com/en/docs/claude-code`
- An **SSH key on this machine added to GitHub** with access to the `sonthanh/*` repos
  (the private vault `ai-brain` requires it): `ssh -T git@github.com` should greet you.

## Quick start (1-click)

```bash
git clone git@github.com:sonthanh/brain-ops.git ~/work/brain-ops
cd ~/work/brain-ops
bun run scripts/bootstrap.ts        # clones repos, writes config, generates plists
# …complete the one-time manual steps it prints (auth, secrets, Claude layer)…
bun run scripts/bootstrap.ts --load # loads + enables every launchd job
```

`bootstrap.ts` is **idempotent** — safe to re-run; it never overwrites an existing config or
secrets file.

### What bootstrap automates
1. Verifies the toolchain (and prints `brew install …` for anything missing).
2. Clones the four repos into `~/work` (skips any that already exist).
3. `bun install` in `brain-ops`.
4. Writes `~/.brain-os/brain-os.config.md` and a `~/.config/brain/env` **skeleton** (never clobbers).
5. Generates all 15 launchd plists from the committed configs.
6. With `--load`: `launchctl bootstrap` + `enable` every job.

### What you must do by hand (one-time)
These need your accounts/credentials and cannot be scripted:

1. **GitHub auth** — `gh auth login` (repo scope; the watchdogs + task jobs call `gh`).
2. **Claude login** — run `claude` once and log in (subscription account — never API keys).
3. **Telegram secrets** — edit `~/.config/brain/env`, fill `TG_BOT_TOKEN` + `TG_CHAT_ID`
   (failure alerts from `run-automation.ts`). File is `chmod 600`.
4. **Claude global layer** — see the next section.

## Claude global layer (`~/.claude`)

Every job is `claude -p`, so it inherits your global Claude config. Copy these from the source Mac
(replace `SOURCE` with its host). **Do not copy `~/.claude/.credentials.json`** — re-auth on the
target with `claude` instead.

```bash
# run on the TARGET machine (junjun-server); needs SSH access to the source Mac
SRC=SOURCE:~/.claude
scp    $SRC/CLAUDE.md      ~/.claude/CLAUDE.md
scp    $SRC/RTK.md         ~/.claude/RTK.md
scp    $SRC/settings.json  ~/.claude/settings.json
scp -r $SRC/rules          ~/.claude/
scp -r $SRC/hooks          ~/.claude/
scp -r $SRC/plugins        ~/.claude/     # brings the brain-os plugin + marketplace cache
```

Notes:
- This machine runs as the **default account** (`~/.claude`), not `~/.claude-emvn`. The plists set
  no `CLAUDE_CONFIG_DIR`, so they use `~/.claude`.
- `settings.json` must keep `enabledPlugins["brain-os@brain-os-marketplace"] = true` — the
  automations depend on brain-os skills. Copying `plugins/` brings the plugin itself.
- **Review `~/.claude/hooks/` for hardcoded absolute paths** after copying. They're fine if the
  target user is also `thanhdo`; adjust if the username differs.
- Alternative to copying `plugins/`: in a `claude` TUI run
  `/plugin marketplace add sonthanh/brain-os-marketplace` then
  `/plugin install brain-os@brain-os-marketplace`.

**5 support jobs** (bash crons + bun watchdogs, generated from `scripts/gen-ops-plists.ts`):

| id | schedule | what |
|---|---|---|
| reap-orca-sessions | every 30 min + at load | safety-net reaper for stray interactive `claude /goal` |
| ci-watchdog | every 30 min | files AFK-fix issues when a watched repo's main goes red |
| gmail-triage-watchdog | every 30 min | dispatches gmail triage if a GitHub cron slot is skipped |

> **Gmail triage itself runs on GitHub Actions (cloud), not launchd** — nothing to migrate for it.
> The `gmail-triage-watchdog` above is only the local safety net that re-dispatches a missed slot.

## Cutover (replace the old Mac)

Once junjun-server is verified, stop the **old** Mac from running the same jobs (otherwise both
double-commit and collide in git). On the OLD Mac:

```bash
UID_NUM=$(id -u)
for p in ~/Library/LaunchAgents/com.brain.automation.*.plist \
         ~/Library/LaunchAgents/com.brain.{reap-orca-sessions,ci-watchdog,gmail-triage-watchdog,codeburn-optimize,triage}.plist; do
  launchctl bootout "gui/$UID_NUM" "$p" 2>/dev/null
done
```

The plist files stay on disk (disabled); delete them if you want a clean machine.

## Gotchas

- **Regenerate plists on the target, don't copy them.** The generators detect the target's bun +
  node paths at generation time. Copying the source Mac's plists would carry a stale node path.
- **`node` must be installed** — the `codeburn-optimize` + `triage` crons shell out to it. Brew
  node (`/opt/homebrew/bin/node`) or nvm both work; the generator picks up whichever `which node`
  finds.
- **Secrets never go in git.** `~/.config/brain/env` and `~/.claude/.credentials.json` are recreated
  on the target, not committed.
- **Username-agnostic.** The registry and generators derive every path from `$HOME`; no `/Users/…`
  is hardcoded. If your global `~/.claude/hooks/` scripts hardcode paths, fix those separately.
